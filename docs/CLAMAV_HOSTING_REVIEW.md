# ClamAV hosting review (founder question 2)

Date: 28 November 2026. Reviews [ADR-0032](adr/0032-supabase-storage-and-malware-scanning.md) as the founder asked. Decision record: [ADR-0036](adr/0036-image-privacy-and-scanner-review.md).

**Finding:** no secure, reliable, no-cost production host for ClamAV is available with the current infrastructure. **The production blocker stays.**

- Production still refuses to start without a real scanner.
- Merchant document uploads stay off on staging (`DOCUMENT_UPLOADS=disabled`).
- Nothing unscanned is ever accepted.

The best candidates need a decision or an asset that does not exist yet. They are listed in the table under §2.

## 1. What ClamAV needs

| Need                         | Detail                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A process that stays running | `clamd` loads its signature database once, then scans files sent over its socket (INSTREAM). Loading the full database takes tens of seconds, so it cannot start on each request.                                                                                                                                                                            |
| Memory                       | ClamAV's documentation asks for at least 2 GiB of RAM for `clamd` with the official databases. When a signature update is reloaded while scanning continues (the default), the old and new databases are both in memory for a while, so about 3 GiB is safer. Setting `ConcurrentDatabaseReload no` saves the memory but pauses scanning during each reload. |
| Disk                         | About 1 GB for the databases (`main`, `daily`, `bytecode`), plus temporary space for the file being scanned.                                                                                                                                                                                                                                                 |
| CPU                          | Low on average. A scan of a 10 MB PDF takes well under a second to a few seconds on one modern core.                                                                                                                                                                                                                                                         |
| Signature updates            | `freshclam` downloads updates from ClamAV's CDN (`database.clamav.net`), usually a few times a day. The CDN rate-limits and blocks hosts that check too often; 12 checks a day or fewer is fine. A scanner with old signatures still runs but misses new threats, so update failures must raise an alert.                                                    |
| Network security             | `clamd` has **no authentication**, and the whole file is sent to it. It must never be reachable from the internet in plain text. JAYS requires TLS in production (`CLAMAV_TLS=true`, for example `stunnel` in front of `clamd`). The port should also be limited to the API's outbound addresses or a private tunnel.                                        |
| Availability                 | JAYS fails closed: if the scanner is down, completing an upload returns `503 SCANNER_UNAVAILABLE`, the file stays unserved, and the user tries again later. Scanner downtime blocks uploads but never lets an unscanned file through.                                                                                                                        |

## 3. What was tested (local, real ClamAV)

On 28 November 2026, in the cloud development environment:

- ClamAV 1.5.4 (`clamd`) was installed from the operating system's packages.
- JAYS's `ClamavScanner` scanned files against it over INSTREAM. A clean fictional PDF passed. The EICAR test file was detected. This used the real-provider test: `CLAMAV_TEST_HOST=127.0.0.1 pnpm --filter @jays/api test:providers`.
- **Limitation:** that environment's network policy blocks ClamAV's signature CDN, so `freshclam` could not download the official databases. `clamd` ran with a one-line local test signature for EICAR only. This proves the protocol, the fail-closed handling and detection reporting with a real daemon. It does **not** prove detection quality, memory use with the full databases, or signature updates. Those need a run with the official databases: locally with `docker compose --profile scanner up -d clamav`, or on the chosen host.

Already covered by automated tests (ADR-0032): a fake `clamd` speaking INSTREAM, and an integration test showing uploads stay pending with `503` while the scanner is down.

## 4. If a no-cost host becomes available: minimum secure setup

1. **Machine:** 64-bit Linux with at least 4 GB of RAM, automatic security updates, and a firewall that allows only the TLS port.
2. **ClamAV:** the official package or Docker image `clamav/clamav`. `freshclam` runs as a service, checking no more than 12 times a day.
3. **TLS in front of `clamd`:** for example `stunnel`, with a certificate. Use client-certificate (mutual) TLS, or an IP allowlist, so only JAYS can connect.
   - JAYS's adapter currently does server-verified TLS. Client certificates would be a small adapter change, made when the host is chosen.
4. **Plain-text port:** `clamd` listens on `127.0.0.1` only.
5. **Monitoring:** alert when the database is more than 2 days old, or when `clamd` is down. Uploads already fail closed with `503`.
6. **JAYS:** set `MALWARE_SCANNER=clamav`, `CLAMAV_HOST`, `CLAMAV_PORT` and `CLAMAV_TLS=true` on the API. Run the real-provider test against the host, then a staging upload test, before production.
7. **Documents:** turn document uploads on (`DOCUMENT_UPLOADS=enabled`) only in production, only after steps 1 to 6, and with the founder's approval.

## 5. What the founder can decide

- **Option A: existing hardware.** If the business has a suitable machine and someone to look after it, the team prepares the exact setup (§4). No new cost.
- **Option B: Oracle Cloud Always Free.** Only if the founder accepts the terms: a card for verification, never upgrading, and the reclamation and capacity risks. Ideally it is paired with Option A as a fallback.
- **Option C: keep the blocker.** No real merchant documents are accepted until a reliable scanner exists. This is the default while no choice is made.

Until then, the product works without document uploads on staging, and production cannot start.
